# SpaceKit · Заявки · сервер

Серверная часть приложения для заявок: вход по телефону, заявки, закрепление клиентов за менеджерами, правила доступа и смены статусов. Проверено на PostgreSQL 16 и тестами (54 штуки, `npm test`).

## Запуск

```bash
cp .env.example .env          # заполнить DATABASE_URL
npm install
npm run migrate:dev           # применить миграции
npm run cli:dev -- staff:set-phone "Филипп Инилеев" "+7 999 123-45-67"   # телефоны сотрудников
npm run dev                   # http://localhost:8080/health
npm test                      # правила доступа и статусов + сквозные тесты API на настоящем Postgres (PGlite)
```

Сборка: `npm run build && npm run migrate && npm start`. После первого `npm install` закоммить `package-lock.json`.

### Важно про боевой запуск

- `NODE_ENV=production` пока **не стартует**: коды входа печатаются в лог, а сервис звонков ещё не подключён (открытый вопрос №2). Это сделано намеренно, чтобы коды не попали в боевые логи. В `Dockerfile` стоит `NODE_ENV=production`, поэтому для проверки в облаке задай `NODE_ENV=staging` (код входа при этом виден в логе контейнера, не открывай такой стенд посторонним).
- `AUTH_PEPPER` в production обязателен (секрет для хэшей кодов). Хранить только в переменных окружения сервера, не в репозитории.
- `TRUST_PROXY_HOPS` — сколько прокси стоит перед сервером (в облаке обычно 1, локально 0). От этого зависит лимит запросов кода по IP: если указать неверно, все пользователи окажутся «одним адресом» или лимит можно будет обойти.

## Что умеет API

| Метод и путь | Кто | Что делает |
|---|---|---|
| `POST /auth/request-code` | все | отправляет код (4 цифры, 5 минут, не больше 3 на номер за 10 минут и 10 с одного IP в час) |
| `POST /auth/verify` | все | проверяет код (5 попыток), выдаёт токен на 30 дней. Новому номеру нужны `name` и `company`: создаётся **отдельная** компания в статусе «ожидает» |
| `GET /me`, `POST /auth/logout` | вошедшие | профиль (с числом непрочитанных и настройкой SMS), выход |
| `PATCH /me` `{smsEnabled}` | вошедшие | включить или отключить SMS у себя (уведомления в приложении остаются) |
| `GET /companies` | менеджер, админ | свои клиенты и ещё никем не взятые (админ видит всех) |
| `POST /companies/:id/claim` | менеджер | взять клиента, которого никто не ведёт |
| `POST /companies/:id/approve` | менеджер клиента, админ | подтвердить компанию и её сотрудников |
| `POST /companies/:id/reassign` | админ | передать клиента другому менеджеру (пишется история) |
| `POST /requests` | заказчик | создать заявку; позиции с известным артикулом подбираются сами |
| `GET /requests`, `GET /requests/:id` | по роли | список и карточка. Чужое не видно и выглядит как «не найдено» |
| `POST /requests/:id/status` | по таблице переходов | смена статуса (`src/statuses.ts`) |
| `PATCH /requests/:id/items/:itemId` | менеджер клиента, админ | подбор позиции и цена, только пока заявка «В обработке» |
| `GET /catalog?q=` | менеджер, админ | поиск по каталогу |
| `POST /requests/:id/ship` | менеджер клиента, сборщик, админ | **отгрузка одной кнопкой**. Без тела отгружает все оставшиеся позиции, с `{itemIds}` — часть (статус «Частично отгружена»). Номер `ОТ-0001`; когда подключим МойСклад, отгрузка в нём создастся этим же вызовом |
| `GET`/`POST /requests/:id/messages` | заказчик, менеджер клиента, админ | чат в заявке (`?after=<id>` для догрузки). Сборщик переписку не видит |
| `GET /notifications?unread=1`, `POST /notifications/:id/read`, `POST /notifications/read-all` | вошедшие | уведомления в приложении |

### SMS клиентам

SMS уходят заказчикам (только подтверждённым, с телефоном и не отключившим SMS) при: подтверждении компании, отправке заявки на подтверждение, отмене менеджером, отгрузке (полной и частичной). Переписка в чате SMS не вызывает.
SMS кладётся в очередь `sms_outbox` в одной транзакции с событием и уходит отдельным воркером (3 попытки с нарастающей паузой, без двойной отправки при нескольких экземплярах). Пока подключён только `ConsoleSmsSender` (печатает в лог): реальный провайдер выбираем вместе с провайдером кодов входа, лучше одного. Переменные: `SMS_PROVIDER` (сейчас только `console`), `APP_URL` (ссылка в конце SMS, необязательно).

Цены заказчик видит только начиная со статуса «На подтверждении» (для отдельной компании можно открыть раньше флагом `companies.show_prices_early`). Отправить на подтверждение можно только если у всех позиций есть подбор и цена.

## Распределение клиентов между менеджерами

- Клиента ведёт один менеджер (`companies.manager_id`); база не даёт указать не менеджера. Менеджер видит и обрабатывает только своих клиентов.
- Нераспределённых клиентов видят все менеджеры, любой может взять (`claim`); если двое жмут одновременно, второй получает отказ. Пока клиент не взят, менять его заявки менеджер не может.
- Компанию подтверждает её менеджер или админ. Переназначать клиентов между менеджерами может только админ; заявки переходят автоматически, потому что владелец заявки определяется по компании.

### Как закрепляются клиенты по списку

Список «менеджер → клиент» хранится как **подсказки** (`client_manager_hints`), потому что точные названия контрагентов станут известны после синхронизации с МоимСкладом.

- Название сравнивается без учёта регистра, `ё`, кавычек и формы собственности в начале: «ООО «Профит Рум»» = «профит рум».
- **Автоматически назначается только точное совпадение**: при регистрации компании или командой `clients:apply-hints`. Подтверждает компанию всё равно её менеджер.
- Приблизительные совпадения (например, подсказка «Бабаев» и компания «Бабаев Иван Петрович») сами не применяются: ошибка спрятала бы клиента от нужного менеджера. Их показывает `clients:suggest`, дальше назначение делает админ (`POST /companies/:id/reassign`) или менеджер (`claim`).
- Команды: `clients:load-hints <файл.csv>` (строки `менеджер;клиент`), `clients:apply-hints`, `clients:suggest`. Файл со списком и телефонами храни локально (`*.local.csv`, `*.local.sh` не попадают в git).

## МойСклад (только чтение)

Токен задаётся **только** переменной окружения `MS_TOKEN` на твоём компьютере или сервере; в файлы, репозиторий и логи он не попадает. Команды можно запускать у себя или в облачной сессии Claude (там ключ подставляет прокси окружения, `MS_TOKEN` можно задать любым):

```
MS_TOKEN=... npm run cli:dev -- ms:check            # токен работает? покажет юрлица
MS_TOKEN=... npm run cli:dev -- ms:counterparties   # контрагенты и сверка с подсказками «менеджер → клиент»
MS_TOKEN=... npm run cli:dev -- ms:sync-catalog     # товары и цены в каталог (МойСклад не меняется)
```

Токен лучше завести отдельный, перевыпустив прежний, который попал в чат.
