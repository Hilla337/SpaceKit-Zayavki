# SpaceKit · Заявки · сервер

Серверная часть приложения для заявок: вход по телефону, заявки, закрепление клиентов за менеджерами, правила доступа и смены статусов. Проверено на PostgreSQL 16 и тестами (87 штук, `npm test`).

## Запуск

```bash
cp .env.example .env          # заполнить DATABASE_URL
npm install
npm run migrate:dev           # применить миграции
npm run cli:dev -- staff:set-phone "Филипп Инилеев" "+7 999 123-45-67"   # телефоны сотрудников
npm run cli:dev -- staff:reset-code "Филипп Инилеев"    # код, по которому сотрудник задаст себе пароль
npm run dev                   # http://localhost:8080/health
npm test                      # правила доступа и статусов + сквозные тесты API на настоящем Postgres (PGlite)
```

Сборка: `npm run build && npm run migrate && npm start`. После первого `npm install` закоммить `package-lock.json`.

### Вход и боевой запуск

- Вход по телефону и паролю, без платных звонков и SMS. Заказчик регистрируется сам; пользоваться приложением можно после того, как менеджер подтвердит компанию.
- Забыли пароль: менеджер в «Клиенты → Люди и пароли» выдаёт своему клиенту одноразовый код (6 цифр, сутки, 5 попыток) и сам отправляет его в WhatsApp; клиент открывает «Забыли пароль?». Сотрудникам код выдаёт админ (там же, блок «Сотрудники») или команда `staff:reset-code`.
- Защита: пароль хранится только хэшем scrypt; 10 неверных паролей подряд закрывают вход на номер на 15 минут; с одного адреса не больше 30 попыток за 15 минут; после сброса пароля все прежние входы закрываются.
- `AUTH_PEPPER` в production обязателен (секрет для хэшей кодов сброса). Хранить только в переменных окружения сервера.
- `SMS_PROVIDER`: в production по умолчанию `none` — SMS не уходят, уведомления остаются в приложении; `console` печатает SMS в лог.
- `TRUST_PROXY_HOPS` — сколько прокси стоит перед сервером (в облаке обычно 1, локально 0). От этого зависит лимит попыток по IP.
- `BOOTSTRAP_ADMIN_PHONE`, `BOOTSTRAP_ADMIN_PASSWORD`, `BOOTSTRAP_ADMIN_NAME` — первый админ при запуске (создаётся один раз, заданный потом пароль не затирается).
- `MS_SYNC_HOURS` с `MS_TOKEN` — каталог из МойСклад (только чтение) при запуске и раз в N часов.
- Стенд в Яндекс Облаке: [deploy/stand/README.md](../deploy/stand/README.md).

## Остатки и обратная связь из МойСклад

- **Остатки**: при `MS_TOKEN` и `MS_SYNC_HOURS` раз в `MS_STOCK_MINUTES` минут (по умолчанию 15) берётся «доступно» по складу `MS_STORE_ID`; менеджер видит «в наличии N» или «нет на складе» в поиске товара, товары в наличии — первыми.
- **Вебхуки** (`MS_WEBHOOKS=1`, нужен `APP_URL` и токен администратора МойСклад): при запуске сервер подписывает МойСклад на отгрузки и изменения заказов по адресу `/ms/webhook/<секрет>` (секрет выводится из `AUTH_PEPPER`). Проведённая в МойСклад отгрузка по заказу из приложения отмечает позиции отгруженными («Частично отгружена» / «Отгружена», заказчику уведомление); статус заказа «Отменен» отменяет заявку; другие смены статуса пишутся в историю. Повторные события ничего не задваивают, чужие заказы пропускаются.
- `MS_DEMANDS=0` — не создавать отгрузки в МойСклад из приложения (так на стенде).

## Push-уведомления

Бесплатные Web Push: каждое уведомление в приложении (новая заявка, сообщение, смена статуса, отгрузка) уходит на устройства человека, где он включил уведомления (настройки или предложение на странице заявок). По нажатию открывается заявка. Ключи VAPID сервер создаёт при первом запуске и хранит в базе (`app_settings`), отдельных секретов не нужно. Нужен HTTPS (на стенде есть). На iPhone уведомления работают только у приложения, добавленного на экран «Домой» (iOS 16.4+).

## Интерфейс

Страница для заказчиков, менеджеров, сборщиков и админа: `server/web/` (`index.html`, `app.css`, `app.js`, без сборки). Её раздаёт этот же сервер на `/`, API на том же адресе.

Посмотреть без базы и без МойСклад:

```bash
npm run dev:memory     # http://localhost:8080, база в памяти, пароль у всех тестовых людей 123456
```

Телефоны в этом режиме: менеджер Филипп `+79990000001`, Татьяна `+79990000002`, сборщик `+79990000008`, админ `+79990000009`, заказчик «Профит Рум» `+79991110001`, пароль у всех `123456`; новый заказчик — кнопка «Регистрация».

Что есть: вход по телефону и коду (новый номер: имя и компания, дальше ждёт подтверждения), список заявок по ролям, новая заявка (объект из прошлых или новый, список товаров, ссылки Петровича, скопированная корзина и файл сметы Петровича .xls или своя таблица .xlsx/.csv разбираются в позиции), подбор товара из каталога и цены, счёт с НДС, отправка на подтверждение, подтверждение заказчиком или менеджером по телефону, просьба изменить, отмена, отгрузка выбранных или всех позиций, переписка, уведомления, клиенты (взять, подтвердить, выбрать контрагента МойСклад поиском, счёт с НДС), отключение SMS.

## Что умеет API

| Метод и путь | Кто | Что делает |
|---|---|---|
| `POST /auth/register` `{phone, password, name, company}` | все | регистрация заказчика: создаётся **отдельная** компания в статусе «ожидает»; занятый номер — `phone_taken` |
| `POST /auth/login` `{phone, password}` | все | вход, токен на 30 дней; неверный пароль и чужой номер отвечают одинаково |
| `POST /auth/reset` `{phone, code, password}` | все | новый пароль по коду от менеджера или админа |
| `POST /users/:id/reset-code` | менеджер своего заказчика, админ — любому | одноразовый код сброса (показывается один раз) |
| `POST /me/password` `{oldPassword, newPassword}` | вошедшие | смена своего пароля, остальные устройства разлогиниваются |
| `GET /companies/:id/users`, `GET /staff` | менеджер клиента / админ | люди компании и сотрудники (для кодов сброса) |
| `POST /staff` `{role, name, phone}`, `PATCH /staff/:id` `{phone}` | админ | добавить сотрудника, задать телефон |
| `POST /hints` `{text}` | админ | список «менеджер;клиент» вставкой текста: загрузить и сразу назначить точные совпадения |
| `GET /me`, `POST /auth/logout` | вошедшие | профиль (с числом непрочитанных и настройкой SMS), выход |
| `PATCH /me` `{smsEnabled}` | вошедшие | включить или отключить SMS у себя (уведомления в приложении остаются) |
| `GET /companies` | менеджер, админ | свои клиенты и ещё никем не взятые (админ видит всех) |
| `POST /companies/:id/claim` | менеджер | взять клиента, которого никто не ведёт |
| `POST /companies/:id/approve` | менеджер клиента, админ | подтвердить компанию и её сотрудников |
| `POST /companies/:id/reassign` | админ | передать клиента другому менеджеру (пишется история) |
| `POST /requests` | заказчик | создать заявку; позиции с известным артикулом подбираются сами |
| `GET /requests`, `GET /requests/:id` | по роли | список и карточка. Чужое не видно и выглядит как «не найдено» |
| `POST /requests/:id/status` | по таблице переходов | смена статуса (`src/statuses.ts`) |
| `PATCH /requests/:id/items/:itemId` | менеджер клиента, админ | подбор позиции и цена, только пока заявка «В обработке» |
| `GET /catalog?q=` | менеджер, админ | поиск по каталогу |
| `GET /objects` | заказчик | объекты своей компании (для новой заявки) |
| `GET /ms/counterparties?q=` | менеджер, админ | поиск контрагента в МойСклад по названию |
| `PATCH /companies/:id` `{vatInvoice}` | менеджер клиента, админ | клиент берёт счёт с НДС (НДС 5% только в счёте; заказ и отгрузка без изменения НДС) |
| `PATCH /requests/:id` `{vatInvoice}` | менеджер клиента, админ | счёт с НДС в этой заявке (до создания заказа в МойСклад) |
| `POST /companies/:id/ms-counterparty` `{msId}` | менеджер клиента, админ | связать компанию с контрагентом МойСклад (проверяется, что он есть; один контрагент — одна компания) |
| `POST /requests/:id/ship` | менеджер клиента, сборщик, админ | **отгрузка одной кнопкой**. Без тела отгружает все оставшиеся позиции, с `{itemIds}` — часть (статус «Частично отгружена»). С МойСклад (`MS_WRITE=1`) этим же вызовом создаётся отгрузка в МойСклад на основании заказа, номер берётся оттуда; без него номер `ОТ-0001` |
| `GET`/`POST /requests/:id/messages` | заказчик, менеджер клиента, админ | чат в заявке (`?after=<id>` для догрузки). Сборщик переписку не видит |
| `GET`/`POST /requests/:id/messages`, `PATCH`/`DELETE /requests/:id/messages/:mid`, `POST …/:mid/reaction` | заказчик, менеджер клиента, админ | переписка: текст, вложение, ответ (`replyToId`), правка и удаление своего (админ удаляет любое), реакции; открытие отмечает прочитанным (`read` у своих сообщений) |
| `POST /requests/:id/attachments?name=&kind=voice&duration=` (тело — байты, `Content-Type: application/octet-stream`, тип в `X-File-Type`), `GET /attachments/:id` | участники переписки | вложения до 25 МБ: фото, видео, голосовые, файлы |
| `GET /staff/managers` | админ | менеджеры для переназначения клиента |
| `GET /push/key`, `POST /push/subscribe`, `POST /push/unsubscribe` | все / вошедшие | push-уведомления в браузер (Web Push): открытый ключ сервера, подписка и отписка устройства |
| `GET /notifications?unread=1`, `POST /notifications/:id/read`, `POST /notifications/read-all` | вошедшие | уведомления в приложении |

### SMS клиентам

SMS уходят заказчикам (только подтверждённым, с телефоном и не отключившим SMS) при: подтверждении компании, отправке заявки на подтверждение, отмене менеджером, отгрузке (полной и частичной). Переписка в чате SMS не вызывает.
SMS кладётся в очередь `sms_outbox` в одной транзакции с событием и уходит отдельным воркером (3 попытки с нарастающей паузой, без двойной отправки при нескольких экземплярах). Пока подключён только `ConsoleSmsSender` (печатает в лог): реальный провайдер выбираем вместе с провайдером кодов входа, лучше одного. Переменные: `SMS_PROVIDER` (сейчас только `console`), `APP_URL` (ссылка в конце SMS, необязательно).

Цены заказчик видит только начиная со статуса «На подтверждении» (для отдельной компании можно открыть раньше флагом `companies.show_prices_early`). Отправить на подтверждение можно только если у всех позиций есть подбор и цена.

## Распределение клиентов между менеджерами

- Клиента ведёт один менеджер (`companies.manager_id`); база не даёт указать не менеджера. Менеджер видит и обрабатывает только своих клиентов.
- Нераспределённых клиентов видят все менеджеры, любой может взять (`claim`); если двое жмут одновременно, второй получает отказ. Пока клиент не взят, менять его заявки менеджер не может.
- Компанию подтверждает её менеджер или админ. Переназначать клиентов между менеджерами может только админ; заявки переходят автоматически, потому что владелец заявки определяется по компании.

### Как закрепляются клиенты по списку

Список «менеджер → клиент» хранится как **подсказки** (`client_manager_hints`), потому что точные названия контрагентов станут известны после синхронизации с МоимСкладом.

- Название сравнивается без учёта регистра, `ё`, кавычек и формы собственности в начале: «ООО «Профит Рум»» = «профит рум».
- **Автоматически назначается только точное совпадение**: при регистрации компании или командой `clients:apply-hints`. Подтверждает компанию всё равно её менеджер.
- Приблизительные совпадения (например, подсказка «Бабаев» и компания «Бабаев Иван Петрович») сами не применяются: ошибка спрятала бы клиента от нужного менеджера. Их показывает `clients:suggest`, дальше назначение делает админ (`POST /companies/:id/reassign`) или менеджер (`claim`).
- Команды: `clients:load-hints <файл.csv>` (строки `менеджер;клиент`), `clients:apply-hints`, `clients:suggest`. Файл со списком и телефонами храни локально (`*.local.csv`, `*.local.sh` не попадают в git).

## МойСклад

Токен задаётся **только** переменной окружения `MS_TOKEN` на твоём компьютере или сервере; в файлы, репозиторий и логи он не попадает. Команды можно запускать у себя или в облачной сессии Claude (там ключ подставляет прокси окружения, `MS_TOKEN` можно задать любым):

```
MS_TOKEN=... npm run cli:dev -- ms:check            # токен работает? покажет юрлица
MS_TOKEN=... npm run cli:dev -- ms:counterparties   # контрагенты и сверка с подсказками «менеджер → клиент»
MS_TOKEN=... npm run cli:dev -- ms:sync-catalog     # товары и «Цена продажи» в каталог (МойСклад не меняется)
```

Токен лучше завести отдельный, перевыпустив прежний, который попал в чат.

**Автоподбор по ссылке Петровича.** У товаров из Петровича «Код» в МойСклад совпадает с кодом на petrovich.ru (6–7 цифр, заполнена «Цена Петрович»; так у 2819 из 8221 товаров на 25.11.2026). Синхронизация записывает им `store = 'Петрович'` и этот код, поэтому позиция, вставленная ссылкой `petrovich.ru/product/<код>`, подбирается сама с «Ценой продажи». У остальных товаров для автоподбора используется уникальный артикул.

### Запись в МойСклад (`MS_WRITE=1`)

- **Подтверждение заявки** (заказчиком или менеджером по телефону) создаёт **заказ покупателя**: контрагент компании, юрлицо `MS_ORGANIZATION_ID`, склад `MS_STORE_ID`, статус `MS_ORDER_STATE` (по умолчанию «Готов к сборке»), позиции из подбора с ценами. По объекту создаётся **проект** с доп. полями (ЖК, улица, дом, …, паркинг и пропуск как да/нет); на следующие заявки по тому же объекту проект переиспользуется.
- **Счёт с НДС.** У Spacekit НДС 5% ставится только в счёте покупателю, заказ и отгрузка идут без изменения НДС (так в 73 из 100 последних счетов). Поэтому приложение НДС в заказ и отгрузку не передаёт. Если в заявке включён `vatInvoice` (берётся от компании, менеджер может поменять до подтверждения), в описании заказа пишется «счёт с НДС» — подсказка менеджеру выставить счёт с 5%.
- **Отгрузка одной кнопкой** создаёт **отгрузку** на основании заказа по выбранным позициям, номер отгрузки берётся из МойСклад.
- Если МойСклад ответил ошибкой, в приложении ничего не меняется, человек получает 502 с текстом ошибки МойСклад. Повторное нажатие не задваивает документы: у каждого свой `externalCode` (`zayavki-req-…`, `zayavki-obj-…`, `zayavki-ship-…`), и перед созданием он ищется.
- Отправить на подтверждение можно, только когда у компании указан контрагент: `POST /companies/:id/ms-counterparty`, `ms:link-companies` (по точному названию, только однозначные) или `ms:link-company <id> <id контрагента>`.

Из облака Claude Node-у нужен `NODE_USE_ENV_PROXY=1`, чтобы ходить через прокси окружения.
