# Тестовый стенд в Яндекс Облаке

Одна виртуальная машина: PostgreSQL 16, приложение и Caddy (сам выпускает HTTPS-сертификат).
Адрес вида `https://158-160-12-34.sslip.io` — домен покупать не нужно. Запускается и обновляется кнопкой в GitHub Actions.

На стенде каталог читается из МойСклад (если задан токен), а **запись в МойСклад выключена**: тестовые заявки не создают настоящих заказов и отгрузок. SMS выключены, уведомления — в приложении.

## Первая настройка (один раз)

### 1. Яндекс Облако
1. В [консоли](https://console.yandex.cloud) выберите или создайте каталог для стенда. Скопируйте его ID (на странице каталога, вида `b1g…`).
2. **Сервисные аккаунты → Создать**: имя `zayavki-deployer`, роль `editor` на этот каталог.
3. Откройте аккаунт → **Создать новый ключ → Авторизованный ключ** → скачайте JSON-файл. Это пароль к облаку: никому не пересылайте, в чат не вставляйте.
4. Нужен активный платёжный аккаунт. Стенд — это ВМ 2 vCPU (20%), 2 ГБ памяти, диск 20 ГБ и статический IP. Стоимость посчитайте в [калькуляторе](https://yandex.cloud/ru/prices); статический адрес оплачивается, даже когда ВМ остановлена.

### 2. Секреты в GitHub
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Что вписать |
|---|---|
| `YC_SA_KEY` | всё содержимое JSON-файла ключа из шага 1.3 |
| `YC_FOLDER_ID` | ID каталога |
| `STAND_SECRET` | любая длинная случайная строка (40+ символов). Из неё выводятся пароль базы и секрет кодов сброса. Не меняйте после запуска: база перестанет открываться |
| `STAND_ADMIN_PHONE` | ваш телефон — станет первым админом |
| `STAND_ADMIN_PASSWORD` | пароль первого админа (не короче 6 символов). Используется только при первом запуске, потом меняется в приложении |
| `STAND_ADMIN_NAME` | необязательно: ваше имя (по умолчанию «Администратор») |
| `STAND_MS_TOKEN` | необязательно: токен МойСклад **только на чтение** — тогда каталог товаров обновляется на стенде раз в 6 часов |

### 3. Запуск
Кнопка запуска появляется, когда файл `.github/workflows/stand.yml` есть в основной ветке `main` (влейте ветку с этим файлом).
Дальше: **Actions → «Стенд в Яндекс Облаке» → Run workflow**. Сценарий:
1. собирает образ приложения и кладёт его в GitHub Packages;
2. создаёт постоянный публичный адрес и ВМ (или обновляет её, база при этом сохраняется);
3. ждёт, пока стенд ответит по HTTPS, и пишет адрес в итог запуска.

**Если первый запуск остановился на шаге «Собрать и опубликовать образ»** с просьбой сделать пакет публичным: github.com/Hilla337/SpaceKit-Zayavki → справа **Packages → spacekit-zayavki → Package settings → Change visibility → Public**, затем снова Run workflow. Это нужно один раз: ВМ скачивает образ без пароля. Код и так публичный, секретов в образе нет.

### 4. Настройка в приложении
Войдите по `STAND_ADMIN_PHONE` и `STAND_ADMIN_PASSWORD` → **Клиенты**:
1. **Менеджеры**: задайте телефоны четырём менеджерам («Задать телефон»), при необходимости добавьте новых.
2. Каждому — **«Код для пароля»**: отправьте код сотруднику, он откроет «Забыли пароль?» и задаст пароль сам.
3. **«Клиенты менеджеров»**: выберите менеджера и вставьте его клиентов по одному в строке — клиенты с точным названием сразу попадут к своему менеджеру.

## Обновить стенд
Снова **Run workflow** — соберётся свежая версия, ВМ перезапустит контейнеры, база останется. В окне Run workflow можно выбрать ветку (**Use workflow from**): так стенд обновляется из рабочей ветки без слияния в `main`.

## Остановить или удалить
В консоли: **Compute Cloud → zayavki-stand → Остановить** (или Удалить). Адрес — **VPC → IP-адреса → zayavki-stand-ip**. Удаление ВМ удаляет и базу стенда.

## Безопасность
- Журналы Actions в публичном репозитории видны всем, поэтому сценарий не печатает секреты, телефоны и ответы `yc` с метаданными ВМ.
- Настройки стенда (пароль базы, токен МойСклад, стартовый пароль админа) лежат в метаданных ВМ: их видят пользователи вашего облачного каталога. Для тестового стенда это допустимо; для боевого — вынести в Lockbox.
- База наружу не открыта: доступна только приложению внутри ВМ. Снаружи открыты только порты 80 и 443.

## Если что-то не так
- **Стенд не ответил за 10 минут.** Первый запуск ВМ и выпуск сертификата иногда идут дольше — запустите сценарий ещё раз. Если не помогает, проверьте группу безопасности сети: должны быть разрешены входящие 80 и 443.
- **Ошибка прав в шаге «Установить и настроить yc».** У сервисного аккаунта нет роли `editor` на каталог `YC_FOLDER_ID`.
