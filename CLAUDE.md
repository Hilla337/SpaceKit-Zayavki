## Кто и зачем
Хозяин (Илья) ведёт финансы и автоматизацию в Spacekit, компании по продаже стройматериалов. Приложение принимает заявки от заказчиков (прорабов): список товаров или корзина с Петровича, который заказчик вставляет сам (robots.txt Петровича запрещает автоматический доступ, не обходить). Менеджер клиента проверяет, подбирает позиции из каталога МойСклад, ставит цены и отправляет заказчику на подтверждение. После подтверждения заявка уходит на сборку и отгрузку. Склад и учёт живут в МойСклад.

## Бизнес-правила (не ломать)
- Клиенты распределены между 4 менеджерами, каждый ведёт своих клиентов эксклюзивно: Филипп Инилеев, Татьяна Чех, Максим Стребков, Дмитрий Барбарасов. Нераспределённых видят все менеджеры, любой может взять (`claim`). Переназначает только админ.
- Назначение по списку «менеджер → клиент» (`client_manager_hints`): автоматически только точное совпадение нормализованного названия, приблизительные только предлагаются (`clients:suggest`). «Да! Долгаймер-строй» это одна компания.
- Лифт в объекте: только `грузовой` / `пассажирский` / `нет`.
- Заказчик не видит цен до статуса «На подтверждении» (флаг `companies.show_prices_early` открывает раньше). На подтверждение можно отправить, только если у всех позиций есть подбор и цена.
- Отгрузка одной кнопкой (`POST /requests/:id/ship`), в том числе частичная. Сменой статуса отгрузить нельзя (`use_shipments`). В МойСклад отгрузка тоже должна создаваться одной кнопкой.
- SMS заказчикам при подтверждении компании, отправке на подтверждение, отмене менеджером и отгрузке. Чат SMS не вызывает. У пользователя можно отключить (`users.sms_enabled`).
- ОТКАЗАНО: схема «вторая накладная для клиента прораба с наценкой +12%, разницу прораб забирает». Не реализовывать. Тема отложена («пока оставим это»). Если вернётся, предлагать легальные варианты: официальное вознаграждение/комиссия или модель перепродажи.

## Технологии
Node.js 22, TypeScript strict (NodeNext ESM, импорты с `.js`), Fastify 5, pg, PostgreSQL 16. Тесты `node:test` через tsx на PGlite (в памяти). Миграции в `server/migrations` (001–007), идемпотентный раннер. Dockerfile есть.

Модули `server/src`: `app.ts` (сборка, `authenticate`), `auth.ts`, `access.ts` (кто что видит; чужое = 404), `statuses.ts` (таблица переходов), `hints.ts`, `services.ts` (история, уведомления, SMS-очередь), `sms.ts` (outbox + воркер с lease, 3 попытки), `routes-*.ts` (auth, companies, requests, ship, chat), `moysklad.ts` (клиент МойСклад: чтение и запись `MsWriter`), `ms-orders.ts` (заказ и отгрузка из заявки), `cli.ts`, `server.ts`.

Вход: телефон + 4-значный код (HMAC с `AUTH_PEPPER`, TTL 5 мин, 5 попыток, ≤3 кода за 10 мин на номер, ≤10 в час с IP), сессии 30 дней, `TRUST_PROXY_HOPS` задаёт число прокси.

## Запуск
```
cd server && npm install
npm test            # 64 теста
npm run typecheck
```
С реальной базой: `DATABASE_URL`, `AUTH_PEPPER`, `npm run migrate:dev`, `npm run dev`. `NODE_ENV=production` пока не стартует, пока нет настоящего отправителя кодов (сделано намеренно). Для стенда ставь `NODE_ENV=staging`. Подробности в `server/README.md`.

## Безопасность
- Токены МойСклад только в переменной окружения `MS_TOKEN`, никогда в файлах, репозитории, логах и истории команд (`read -s MS_TOKEN; export MS_TOKEN`).
- Хозяин присылал токены МойСклад в чат. Их нужно отозвать и выпустить новый, лучше отдельный и только на чтение, пока не начнём запись.
- Файлы `*.local.csv` и `*.local.sh` (список клиентов по менеджерам и телефоны) содержат личные данные, в git не коммитить. В эту выгрузку они не включены.
