## Кто и зачем
Хозяин (Илья) ведёт финансы и автоматизацию в Spacekit, компании по продаже стройматериалов. Приложение принимает заявки от заказчиков (прорабов): список товаров или корзина с Петровича, который заказчик вставляет сам (robots.txt Петровича запрещает автоматический доступ, не обходить). Менеджер клиента проверяет, подбирает позиции из каталога МойСклад, ставит цены и отправляет заказчику на подтверждение. После подтверждения заявка уходит на сборку и отгрузку. Склад и учёт живут в МойСклад.

## Бизнес-правила (не ломать)
- Клиенты распределены между 4 менеджерами, каждый ведёт своих клиентов эксклюзивно: Филипп Инилеев, Татьяна Чех, Максим Стребков, Дмитрий Барбарасов. Нераспределённых видят все менеджеры, любой может взять (`claim`). Переназначает только админ.
- Назначение по списку «менеджер → клиент» (`client_manager_hints`): автоматически только точное совпадение нормализованного названия, приблизительные только предлагаются (`clients:suggest`). «Да! Долгаймер-строй» это одна компания.
- Лифт в объекте: только `грузовой` / `пассажирский` / `нет`.
- Заказчик не видит цен до статуса «На подтверждении» (флаг `companies.show_prices_early` открывает раньше). На подтверждение можно отправить, только если у всех позиций есть подбор и цена.
- Отгрузка одной кнопкой (`POST /requests/:id/ship`), в том числе частичная. Сменой статуса отгрузить нельзя (`use_shipments`). В МойСклад отгрузка тоже должна создаваться одной кнопкой.
- SMS заказчикам при подтверждении компании, отправке на подтверждение, отмене менеджером и отгрузке. Чат SMS не вызывает. У пользователя можно отключить (`users.sms_enabled`). SMS платные, поэтому в production по умолчанию выключены (`SMS_PROVIDER=none`): очередь не пополняется, переключатель в настройках скрыт, уведомления остаются в приложении.
- НДС 5% только в счёте покупателю и только клиентам, которые берут счёт с НДС (правило хозяина, 25.11.2026). В заказ и отгрузку НДС не передаём. Флаг `companies.vat_invoice`, заявка копирует его в `requests.vat_invoice` (менеджер может поменять до создания заказа); сейчас он только пишет «счёт с НДС» в описание заказа, счёт выставляет менеджер.
- Сборщики: у них будет отдельное приложение для логистики (решение хозяина 25.11.2026). Роль сборщика в этом приложении пока оставляем как есть, не развиваем.
- Оформление: бежевая палитра по логотипу (`server/web/logo.png`, фон логотипа #e4e0d7), плавные анимации.
- ОТКАЗАНО: схема «вторая накладная для клиента прораба с наценкой +12%, разницу прораб забирает». Не реализовывать. Тема отложена («пока оставим это»). Если вернётся, предлагать легальные варианты: официальное вознаграждение/комиссия или модель перепродажи.

## Технологии
Node.js 22, TypeScript strict (NodeNext ESM, импорты с `.js`), Fastify 5, pg, PostgreSQL 16. Тесты `node:test` через tsx на PGlite (в памяти). Миграции в `server/migrations` (001–012), идемпотентный раннер. Dockerfile есть.

Модули `server/src`: `app.ts` (сборка, `authenticate`), `auth.ts`, `bootstrap.ts` (первый админ из окружения), `access.ts` (кто что видит; чужое = 404), `statuses.ts` (таблица переходов), `hints.ts`, `services.ts` (история, уведомления, SMS-очередь), `sms.ts` (outbox + воркер с lease, 3 попытки), `routes-*.ts` (auth, companies, requests, ship, chat), `moysklad.ts` (клиент МойСклад: чтение и запись `MsWriter`), `ms-orders.ts` (заказ и отгрузка из заявки), `ms-webhook.ts` (обратная связь из МойСклад: отгрузки и статусы заказов), `push.ts` (Web Push: ключи VAPID в `app_settings`, воркер по `notifications.pushed_at`), `cli.ts`, `server.ts`.

Вход: телефон + пароль (решение хозяина 26.11.2026: ничего платного для входа не подключаем). Пароль — хэш scrypt; 10 неверных подряд → номер закрыт на 15 мин; ≤30 попыток за 15 мин с IP. Регистрация заказчика сама (`/auth/register`), пользоваться можно после подтверждения компании менеджером. Забыл пароль — менеджер своего клиента (сотруднику — админ, или CLI `staff:reset-code`) выдаёт одноразовый 6-значный код на сутки (`POST /users/:id/reset-code`, HMAC с `AUTH_PEPPER`, 5 попыток) и сам отправляет его в WhatsApp; клиент вводит телефон, код и новый пароль (`/auth/reset`, все прежние сессии закрываются). Смена своего пароля `/me/password`. Сессии 30 дней, `TRUST_PROXY_HOPS` задаёт число прокси.

## Запуск
```
cd server && npm install
npm test            # 87 тестов
npm run dev:memory  # интерфейс на http://localhost:8080 без базы и МойСклад (PGlite, поддельный МойСклад, пароль у всех 123456)
npm run typecheck
```
С реальной базой: `DATABASE_URL`, `AUTH_PEPPER`, `npm run migrate:dev`, `npm run dev`. `NODE_ENV=production` требует `AUTH_PEPPER`. Первому админу пароль задаётся так: `staff:add admin` (или `staff:set-phone`), затем `staff:reset-code "Имя"` и «Забыли пароль?» в приложении. Подробности в `server/README.md`.

## Безопасность
- Токены МойСклад только в переменной окружения `MS_TOKEN`, никогда в файлах, репозитории, логах и истории команд (`read -s MS_TOKEN; export MS_TOKEN`).
- Хозяин присылал токены МойСклад в чат. Их нужно отозвать и выпустить новый, лучше отдельный и только на чтение, пока не начнём запись.
- Файлы `*.local.csv` и `*.local.sh` (список клиентов по менеджерам и телефоны) содержат личные данные, в git не коммитить. В эту выгрузку они не включены.

## Сделано
Вход и сессии, изоляция данных по менеджерам, статусы, видимость цен, подсказки по клиентам, заявки и подбор, отгрузки (полные и частичные), чат, уведомления, SMS-очередь (пока консольный отправитель), МойСклад: чтение (`ms:check`, `ms:counterparties`, `ms:sync-catalog`) и запись при `MS_WRITE=1`: заказ покупателя с проектом при подтверждении, отгрузка на основании заказа одной кнопкой (номер из МойСклад), идемпотентно по `externalCode`; сбой МойСклад ничего не меняет в приложении. Компания связывается с контрагентом (`ms_counterparty_id`), без него на подтверждение не отправить. 25.11.2026 запись проверена на настоящем аккаунте (с согласия хозяина): заказ на SOMARI в статусе «Тест :3», проект, две отгрузки (частичная и остаток) легли правильно, затем удалены, остатки вернулись. Юрлицо ИП Рашевский, склад «Основной склад» (ID в `server/.env.example`). Каталог: «Цена продажи» по названию; товары с кодом Петровича (6–7 цифр + «Цена Петрович») подбираются автоматически по ссылке на товар Петровича (`/product/<код>`, `/catalog/…/<код>/`, `?code=`). Ссылку на корзину прочитать нельзя (robots.txt): строка сохраняется с пометкой для менеджера, заказчику предлагается скопировать список товаров из корзины; разбор скопированного текста корзины — ждём пример от хозяина. «API Петровича» с GitHub (petrovich_framework) — это обёртка автотестов над их внутренним API, не подключать. Интерфейс `server/web/` (index.html, app.css, app.js; чистый JS без сборки, сервер раздаёт на `/`, ставится на телефон как приложение — manifest + sw.js): все роли, весь путь заявки, клиенты (админ переназначает менеджера), контрагент МойСклад поиском, НДС-флаг, уведомления; чат как в Telegram: фото, видео, файлы, голосовые (запись в браузере), эмодзи, ответ, правка, удаление, реакции, ✓✓ прочитано, вставка из буфера и перетаскивание, просмотр фото на весь экран (вложения в таблице `attachments`, bytea, до 25 МБ); проверен сквозным прогоном в браузере (заказчик → менеджер → заказчик → сборщик, регистрация нового номера, мобильная ширина). `demo/index.html` — демо без сервера: тот же интерфейс + «сервер в браузере» `server/web-demo/mock.js` (те же правила, тестовые данные, переключатель ролей); собирается `node server/web-demo/build-demo.mjs`, опубликовано: https://claude.ai/artifact/NbgyK2wRRT5gv3oKQAxqK4 (после изменений интерфейса пересобрать и переопубликовать). В демо нет записи голоса и скачивания файлов (ограничения страницы claude.ai).
